Amortize is a self-hosted cost-control proxy for enterprise AI agents. LIGHTEN
cuts the eight-tool schema context 65.4%; one live pair used 15.2% fewer input
tokens with field-exact parity. Snowflake records run economics, while a signed

## 50-word description — use after the repeat gate passes

Enterprises pay AI agents to rediscover the same workflows. Amortize is a
self-hosted proxy that shrinks tool context on new tasks, reuses guarded
procedures on repeats, and measures cost per successful task. One endpoint
routes compatible agents through it; Snowflake makes every token, step, and
verified saving queryable.

## 150-word description — final gate-controlled version

Enterprises are deploying AI agents across support, engineering, operations,
and finance, but their unit economics reset on every run. The same tool manuals
return to context, and the same successful workflow is reasoned through again.

Amortize is a self-hosted cost-control proxy with three product acts. LIGHTEN
reveals only the tool context a new task needs. REPLAY converts agreeing
successful Cases into guarded, versioned Skills for repeated work. PROVE
records every run and step's tokens, dollars, model, latency, and backend in a
Snowflake-compatible ledger; the signed demo report records parity and
ground-truth accuracy.

The demo holds model, 30 tickets, eight tools, task prompt, and 120-field grader
constant across direct and Amortize paths, new and repeated. Internal optimizer
calls count toward the total. A saving fails when quality fails. Teams adopt by
changing one model endpoint—no proprietary agent SDK or application rewrite.

Use this version after REPLAY joins LIGHTEN in passing its executable gate.

## Problem

Agent fleets have no durable unit-economics loop. Context is over-sent,
successful procedures are recomputed, and provider invoices cannot explain the
cost of a successful business task.

## Solution

A fail-open proxy, fair-race harness, and Agent Economics Receipt that connect
run economics to a deterministic quality verdict.

## Why Snowflake?

Snowflake stores the run and step trace across models, tools, internal
optimization work, tokens, dollars, latency, and backend. It makes agent
economics queryable by engineering and finance and becomes the data foundation
for future budgets, routing, governance, and chargeback. The current parity and
accuracy verdict is joined from the signed demo report, not claimed as an
already persisted Snowflake grade event.

## Track selection

**Primary: Cost of Intelligence.** Executable gates require measured schema-
token and repeat-cost reductions with an unchanged graded output.

**Secondary: Wildcard.** Amortize creates an agent-economics layer for budgets,
chargeback, policy, and verified procedural reuse.

## Technical differentiation

- One endpoint for supported OpenAI- and Anthropic-compatible clients.
- Optimizes context and repeated procedures—not only provider routing.
- Candidate Skills do not replay; verified Skills require guards and fallback.
- Internal optimization calls are included in usage.
- Savings fail when parity or ground-truth accuracy fails.
- Snowflake and SQLite share the ledger shape.
- Stage replay preserves the demo when the network fails and remains labeled.

## Business path

The open-source local proxy is the adoption wedge. A paid control plane can add
shared Skill governance, policy, budgets, managed reporting, retention,
SSO/RBAC, chargeback, VPC deployment, and fleet analytics. This is a product
and pricing hypothesis, not current revenue.

## Three-minute demo steps

1. Start on a completed 30-ticket workflow; show the repeat cost reset.
2. Reveal the one-base-URL integration.
3. State the fair-race constants.
4. Reveal cold raw dollars, reduction, parity, and accuracy.
5. Reveal repeat raw dollars, guarded Skill state, reduction, and accuracy.
6. Join the Snowflake economics row to the signed report by run ID.
7. Land with one workflow and expand to the enterprise fleet.
